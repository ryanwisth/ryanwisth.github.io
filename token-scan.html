Cost analytics · cause first, then the cut

Finding where the AI budget went

Read-only scripts that scan Claude Code's own session logs and report where the tokens went: by project, model, day, session and tool.

Problem
Claude Code's usage meter shows a total, not a cause. When a week's budget ran out early, I needed to know which projects, sessions and habits spent it.
Result
Six read-only scans turned vague overspending into fixable causes: 482 of 662 helper agents ran as the heavy default type, at 53.8k tokens per first call against 16k to 20k for lean types, and 39% of cache reads came in long unattended turns a per-prompt check never saw. Each finding became a rule in my token guard.

The problem

Every API call's token usage is already written into local log files, but nothing aggregated it, so the meter could not say which project, model, day, session or tool drove the spend. Without a cause, every fix was a guess.

Decisions I made

  • One comparable number. Each call gets one weighted figure from API-style price ratios, so a cheap cache read and an expensive output token land on the same scale. It is a yardstick for comparison, not a bill.
  • Count each call once. Streamed replies span several log lines, so calls are de-duplicated by message ID.
  • One question per pass. Six short, independent scripts each print one table: totals, heavy tool results and images, causes of cache rewrites, kinds of session, re-reading of notes, and usage by model. Each answer can be checked and re-run on its own.
  • Read-only and local. Standard library only; nothing leaves the machine.
  • Heuristics stated, not hidden. Where a script has to guess, the rule is written down and the measured constants can be overridden, so every figure can be traced back to its rule.

How it was verified

  • Drove a real weekly usage review in November 2026, and kept as reusable tools afterwards.
  • The findings became rules in claude-code-token-guard, aimed squarely at the heavy agent type behind 482 of 662 spawns and the unattended turns behind 39% of cache reads.
  • Each new rule was checked against the following week's scan, so the same scripts that found a leak confirmed it closed.

Scope

  • Reads Claude Code's internal log format, which can change between versions.
