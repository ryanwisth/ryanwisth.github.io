Case study: measuring cost before cutting it

Finding where the AI budget went

Read-only scripts that scan Claude Code's own session logs and report where the tokens went: by project, model, day, session and tool. They turned "the weekly allowance ran out early" into specific causes that could be fixed.

The problem

Claude Code's usage meter shows a total, not a cause. When a week's usage ran out early, the useful questions were which projects, sessions and habits spent it.

Every API call's token usage is already written into local log files. Nothing aggregated it.

What I directed

I set the questions each pass had to answer and the weighting, checked the output, and used the results to change how I run agents. The agent wrote the code.

  • One comparable number. Raw token counts mix very different costs, so each call gets one weighted figure based on API-style price ratios. It is a yardstick for comparison, not a bill.
  • Count each call once. A streamed reply can appear on several log lines, so calls are de-duplicated by message ID.
  • One question per pass. Six short, independent scripts, each printing one table: totals, heavy tool results and images, causes of cache rewrites, kinds of session, re-reading of notes, and usage by model.
  • Read-only and local. Standard library only; nothing is sent anywhere.
  • Heuristics stated, not hidden. Where a script has to guess, such as what kind of session a log belongs to, the rule is written down and the measured constants can be overridden.

How the results were verified

  • Used for a real weekly usage review in November 2026, and kept as reusable tools afterwards.
  • The findings were acted on in claude-code-token-guard, and each new rule was checked against the following week's scan.
  • The public copy was checked on a small synthetic log, not on real data.

The outcome

The scan turned vague overspending into specific, fixable causes. Most spawned agents were the expensive default type. Images stayed in context long after they were needed. And 39% of cache reads happened in long unattended turns that a per-prompt check never saw.

Each of those became a rule enforced in code by the token guard, rather than a reminder in a prompt.

Honest limits

  • The log format is Claude Code's internal format, not a documented API, and can change between versions.
  • Session-kind detection relies on wording in Claude Code's own messages and will drift if that wording changes.
  • The figures above were measured on one person's logs; there are no automated tests.
