AI feedback written in ink, and a colour e-ink display decoded safely

Two projects on one reMarkable Paper Pro. Press a Grade button, and an AI model reviews the handwritten work on that page and writes its feedback back onto the page as real pen strokes. Separately, interoperability research worked out how the tablet drives its colour e-ink panel, well enough to draw on the screen with our own code instead of the vendor's library.

Problem
Getting feedback on handwritten work usually means retyping the work into a computer or photographing it. And the tablet's screen is driven by a closed library, so nobody can write software that draws on the display directly.
Result
Tap a button and the tablet returns checked, handwritten-style feedback on the page in seconds, 24 pages per batch, with the student's own ink never altered. On the display, 314 waveform files were decoded and verified, and my own code drew directly on the colour e-ink panel in three update modes.

The problem

Working problems by hand on paper-like e-ink is good for learning. The goal was to close the feedback loop on the device itself: write, tap Grade, and a few seconds later the margin shows a verdict, the mistake struck through, and the worked continuation from where things went wrong.

On the display side, the wrong drive signals can permanently ghost or damage an e-ink panel, so every step had to be safe by design.

Decisions I made

  • Never touch the student's ink. Feedback goes into its own "AI Feedback" layer; skipping a mark beats writing over someone's work.
  • Button-triggered only. Nothing grades in the background. The Grade button grades the current page, a set number of pages, or the whole notebook.
  • Legible handwriting over clever handwriting. Neural handwriting generators failed on math symbols and digits, so the feedback uses a single-stroke font with natural pen movement.
  • Read-only before write. Everything learnable from the public software update was learned first; writing began only once the decoded files predicted the stock frames, and the first write replayed the panel's own boot sequence.
  • Protect the panel by design. Each plan is built so every pixel's drive nets to zero or close to it, and the player refuses a plan built for a different temperature band.

How it was verified

  • Every equation the reviewer wants to write is evaluated in code before it is inked. False ones are dropped.
  • A fingerprint of the student's strokes stops an unchanged page from being graded twice.
  • The full loop (button press, capture, review, ink in the feedback layer) was built and used on the device in August 2026, including 24-page batches.
  • A scale bug that drew ink 18% too large on Letter-size worksheets was traced to the coordinate math and fixed.
  • All 314 waveform files decode and pass their CRC-32 and header checksums.
  • A checker compared frames captured from the stock software against the decoded waveforms.
  • Each display finding is labelled by evidence level: verified on the device, verified by static analysis only, or inferred and not yet verified.

Scope

  • Built and tested on a reMarkable Paper Pro running OS 3.27.3.
  • Independent interoperability research, not affiliated with reMarkable or E Ink. The repository ships the decoders, the frame builder and a tablet-side player; no vendor code, firmware or waveform data is distributed.
