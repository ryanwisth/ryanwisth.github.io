AI on my own devices · working out how a screen draws

AI feedback, handwritten onto a paper tablet

Two projects on one reMarkable Paper Pro, a tablet that feels like writing on paper. Press a Grade button, and an AI checks the handwritten work on the page, then writes its notes back onto it in pen strokes. Separately, I worked out how the tablet’s color screen draws, well enough to draw on it with my own code.

Problem
Getting feedback on handwritten work usually means retyping it or taking a photo. And only the maker’s own locked code can draw on the tablet’s screen.
Result
Built and used on the tablet in August 2026. Tap Grade, and within seconds the page shows a verdict, the mistake crossed out, and the next steps, in handwriting-style ink, up to 24 pages at a time. Every equation is checked by a program first, and the student’s own writing is changed 0 times. All 314 of the screen’s drawing files (called waveforms) were decoded and pass their error checks. My own code then drew on the color screen in three modes, from 11 steps (about 0.13 s) for fast black-and-white to 86 (about 1 s) for full color.

The problem

Working problems by hand on a paper-like screen is good for learning. But getting feedback means taking the work off the page. I wanted feedback on the tablet itself: write, tap Grade, and a few seconds later the margin shows a verdict, the mistake crossed out, and the next steps from where things went wrong.

On the screen side, only the maker’s locked code could draw. The wrong signals can leave lasting marks on this kind of screen or damage it, so every step had to be safe by design.

Decisions I made

  • Never change the student’s writing. Notes go on their own “AI Feedback” layer that the student can delete. The link to the tablet has 0 erase or delete commands, so the worst case is a missed note, never damaged work.
  • Runs only on a tap. Nothing grades in the background. The button grades the current page, a set number of pages, or the whole notebook. The student decides when feedback appears.
  • Two-step review. A fast AI handles clean, correct pages. Anything doubtful goes to a stronger AI, so the costly one is used only where a page needs it.
  • Describe what the page shows, not why. The AI’s instructions forbid guessing why a mistake happened, and remarks about motives or feelings are filtered out. Feedback stays on the work.
  • Readable handwriting over fancy handwriting. AI handwriting tools garbled math symbols and digits. So the notes use a simple pen-stroke font with natural movement that keeps every digit and symbol readable.
  • Look before changing anything. Everything that could be learned from the public software update was learned first. Drawing began only once the decoded files predicted what the tablet’s own software does. The first drawing replayed what the screen already gets at every start-up, to keep risk low.
  • Protect the screen by design. Each plan is built so the push on every dot evens out to zero, or close to it. A plan made for a different temperature range is refused, so a mismatched plan never reaches the screen.

How it was tested

  • No wrong math on the page. Every equation the AI wants to write is checked by a program first. Wrong ones are dropped, so an AI mistake never reaches the page.
  • No double grading. A fingerprint of the student’s strokes stops an unchanged page from being graded twice. Pressing Grade again never piles up repeat notes.
  • Used for real. The whole process (tap, copy, review, notes on their own layer) was built and used on the tablet in August 2026, including 24 pages at a time.
  • Bugs traced to the cause. A bug drew notes 18% too large on Letter-size worksheets. It was traced to the position math and fixed.
  • The decoded files are intact. All 314 drawing files decode and pass their error checks, so every file the drawing code relies on is whole.
  • Predictions matched the screen before any drawing. What the tablet’s own software sends was compared with the decoded files, confirming they describe what the screen really gets.
  • My own code drew on the screen: a replay of the start-up sequence, a black-and-white test card, color cards in three modes, a redraw of part of the screen without clearing it, and two gray levels.
  • Every finding says how sure it is: confirmed on the tablet, confirmed only by reading the code, or a best guess. So each claim says how far it has been proven.

Scope

  • Built and tested on a reMarkable Paper Pro running OS 3.27.3.
  • Independent research, not linked to reMarkable or E Ink. My code includes the decoders, the plan builder and a player that runs on the tablet. None of the maker’s code, software or drawing files is shared.
