AI tooling · guardrails for unattended agents

Long agent jobs with the bill checked first

A small command-line runner that sends a written brief to Claude through the Claude Agent SDK, with explicit auth, budget and turn guards, and loops fresh passes until the brief's done file appears.

Problem
Long agent jobs are easier to hand off as a written brief than as a live chat. Running them unattended raises three questions: which account pays, how to stop a run that goes over budget, and how to continue a job that does not finish in one pass.
Result
Ran real multi-pass agent jobs in October 2026, on the subscription login by default since 2026-10-25. Every run confirms who pays before any work, caps each pass at $20 by default, loops fresh passes until the brief’s done file appears, and stops on the first failed pass with 0 retries.

The problem

An API-key run bills that key's account; a subscription run draws on the subscription. If a key happens to be set, it silently wins over the login, so an unattended run could bill the wrong account. The runner closes that gap: the session’s reported key source must match the --auth flag, or the run aborts with no work done.

Decisions I made

  • Who pays is checked, not assumed. The runner aborts before the first tool call if the session's reported key source does not match the flag.
  • Use the built-in budget. The SDK reports cost only in its final message, so a hand-rolled running total could not stop a run in time.
  • Fresh passes over one long session. A new pass reading short progress notes is cheaper than dragging a full transcript along.
  • Stop on the first failure. A crashed or capped pass needs a person to look before more money is spent, so the loop does not retry.
  • Standing rules apply unattended. The runner loads user and project settings, so the operator's rules govern every run.
  • Spend nothing on a bad command. The loop validates its arguments before any pass starts.

How it was verified

  • The exact key-source string was confirmed by a live test with the smallest model.
  • The auth guard, settings loading, a fresh run and a resume were tested with the smallest model before the first real brief.

Scope

  • The agent runs tools without asking by default, so point it at a folder it is allowed to change.
  • Stopping a pass by hand part-way can leave that folder mid-edit.
