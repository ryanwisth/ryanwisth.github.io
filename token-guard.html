Rules in code, not in the prompt

Spending rules an AI agent cannot forget

Four small hooks and nine cost-tiered subagent types that stop a Claude Code session, and the agents it spawns, from spending far more tokens than the work needs.

The problem

An AI coding agent re-reads its whole conversation on every tool call. Three habits make that expensive without making the work better:

  • Long sessions. A chat at 250k tokens of context pays 250k on every call, including the call that renames a variable.
  • Unpinned subagents. A spawned agent with no model named inherits the session's model, so one "fan out 20 agents" step runs 20 copies of the most expensive model.
  • Heavy tool results. One whole-file read of a large log, or one full-size screenshot, stays in context for every later call.

Written rules in a prompt did not hold: the agent agreed with them and broke them an hour later.

What I directed

I found each leak by measuring my own session logs, set the rule and the thresholds, and checked that each hook changed the numbers in the following week's scan. The agents wrote most of the code.

  • Enforce at the tool call, not in the prompt. A rule in a system prompt is advice. A denied tool call is a fact the agent has to work around, and the denial text tells it how.
  • Two context lines, not one. The soft line gives the agent a turn to save its state while it still has room; the hard line guarantees the session ends. A single hard stop loses the state.
  • A per-call guard as well as a per-prompt guard. The prompt hook only fires when a person types, and 39% of one week's cache reads happened above the soft line, mostly inside long unattended turns. The per-call hook closes that gap.
  • Saving state is always allowed. Past the hard line the agent can still edit its state file and run shell commands, so a blocked session ends with its state written down and not a dead end.
  • Deny the default agent type. Nine lean types each fix a model, a turn cap and a short tool list, so a spawned agent starts small and cannot run away. Making lean the only path that passes fixed the 482 of 662; an opt-out line covers the rare agent that needs browser or MCP (Model Context Protocol) tools.
  • Fail open. On any parse error or missing transcript the hooks exit silently and the tool call proceeds.

How the results were verified

  • Each hook was added after measuring a specific leak in real session logs, and I checked that it changed the numbers in the following week's scan. The measuring side is its own case study: Finding where the AI budget went.
  • Sample hook inputs were piped through each script: 15 cases covering the allow and deny paths for all four hooks behave as described.

The outcome

In daily use on one machine since October 2026. Every denial message says what to do instead, so the agent corrects itself on the next call without me stepping in.

The thresholds are environment variables, so the lines can be moved without editing the hooks.

Honest limits

  • There is no automated test suite.
  • The thresholds were tuned for one person's usage and plan. Treat them as starting points.
  • The per-call hook measures the lead chat's context, so once the lead chat is over the limit it also stops that chat's subagents, even when their own context is small.
  • The token count is the last call's context size, not a prediction of the next one.
  • The image check uses a tool that ships with macOS; on other systems it is skipped.
