Spending rules an AI can’t skip

Claude Code is an AI assistant that writes code for me, and it can hand parts of a job to AI helpers. Four small automatic checks, and nine cheaper kinds of helper, stop it from using far more than the work needs.

Problem
AI use is measured in tokens, small chunks of text the AI reads or writes. Spending rules written into my instructions did not hold: the AI agreed with them and broke them an hour later.
Result
In daily use since October 2026. Four checks and nine lighter helper types block the waste my scans measured. That includes the 482 of 662 helpers that ran as the heavy default type: 53.8k tokens in the first step, against 16k to 20k. Every block says how to fix it, so the AI corrects itself on its next try without me stepping in.

The problem

The AI re-reads the whole chat on every step. So three habits multiply the cost without improving the work:

  • Long chats. A chat that holds 250k tokens pays for 250k on every step.
  • Helpers with no model named. A helper started without naming an AI model gets the main chat’s model.
  • Heavy results. One read of a whole large file, or one full-size screenshot, stays in the chat and is paid for on every later step.

Decisions I made

  • Check every step, not just my instructions. A blocked step is a fact the AI must work around, and the block message tells it how.
  • Two size limits, not one. The soft limit at 200k gives the AI one turn to save its progress. Over 240k, new messages are blocked with a ready-to-paste start for a fresh chat, so a chat always ends with a clean handoff.
  • Guard every step, not just every message. The message check runs only when a person types. Yet 39% of one week’s re-reading came past the soft limit, mostly during long stretches with nobody typing. The check on every step closes that gap: past 260k, any work that is not saving progress is blocked.
  • Saving progress is always allowed. A blocked chat ends with its progress written down, never at a dead end.
  • Block the heavy default helper. Nine lighter helper types, each with a set AI model, a step limit and few tools, became the only way through. That fixed the 482 of 662.
  • Images cost the most. One week held 4,816 images in the chat, so large originals are now blocked, and the message gives the exact command to shrink them.
  • When unsure, step aside. If a check hits an error or can’t find the chat log, it quietly lets the step run, so the guard can never break a working chat.

How it was tested

  • Each check targets a leak measured in my real logs, and each moved the numbers in the next week’s scan: Finding where my AI spending went.
  • 15 sample cases, covering what each of the four checks allows and blocks, behave as described.

Limits

  • The limits are set for my own usage and plan; treat them as starting points.
