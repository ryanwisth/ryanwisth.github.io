Developer tooling · rules enforced in code

Spending rules an AI agent cannot forget

Four small hooks and nine cost-tiered subagent types that stop a Claude Code session, and the agents it spawns, from spending far more tokens than the work needs.

Problem
Spending rules written into a prompt did not hold: the agent agreed with them and broke them an hour later.
Result
In daily use since October 2026: four hooks and nine lean agent types block the waste my scans measured, including the 482 of 662 helper agents that ran as the heavy default type at 53.8k tokens per first call against 16k to 20k. Every denial names the fix, so the agent corrects itself on the next call without me stepping in.

The problem

An AI coding agent re-reads its whole conversation on every tool call, so three habits multiply cost without improving the work:

  • Long sessions. A chat at 250k tokens of context pays 250k on every call.
  • Unpinned subagents. A spawned agent with no model named inherits the session's model.
  • Heavy tool results. One whole-file read of a large log, or one full-size screenshot, stays in context for every later call.

Decisions I made

  • Enforce at the tool call, not in the prompt. A denied call is a fact the agent must work around, and the denial text tells it how.
  • Two context lines, not one. The soft line at 200k gives the agent a turn to save its state; over 240k the prompt is blocked with a paste-ready opener for a fresh chat, so the session always ends with a clean handoff.
  • Guard every call, not just every prompt. The prompt hook fires only when a person types, yet 39% of one week’s re-read context came past the soft line, mostly inside long unattended turns. The per-call hook closes that gap, denying work past 260k that is not saving state.
  • Saving state is always allowed. A blocked session ends with its state written down, never at a dead end.
  • Deny the default agent type. Making the nine lean types, each with a fixed model, turn cap and short tool list, the only path that passes fixed the 482 of 662.
  • Images are the worst tool result. One week held 4,816 image reads in context, so the read hook denies wide originals and prints the exact downscale command.
  • Fail open. On any parse error or missing transcript the hooks exit silently and the call proceeds, so the guard can never break a working session.

How it was verified

  • Each hook targets a leak measured in real session logs, and each moved the numbers in the following week's scan: Finding where the AI budget went.
  • 15 sample inputs covering the allow and deny paths of all four hooks behave as described.

Scope

  • Thresholds are tuned to my usage and plan; treat them as starting points.
