AI reliability · three tools in use

Making AI work checkable

One principle applied in three tools: the AI proposes, code enforces the rules, and a second pass tries to refute the first.

Problem
AI output reads well and is wrong in places, and reading it will not tell you where. Asking the model to check itself gives a second confident answer with no record behind it.
Result
Three tools that turn AI output into checked, logged work. The claim ledger checked and logged 517 claims in one AI-written report; skeptic agents in the research pipeline rejected 3 of 147 claims from a careful pass; and the token guard now holds every helper agent to the lean type, after 482 of 662 had run as the heavy one. The claim ledger and the token guard have been in daily use since October 2026; the pipeline ran three research rounds in September 2026.

The problem

Asking the model to "double-check" gives a second confident pass with no record of what was checked or how.

Written rules do not fix this. In my own sessions the agent agreed with the rules and broke them an hour later. The fix had to live in code, where a rule cannot be forgotten.

Decisions I made

  • Research: genealogy-evidence-pipeline. Every claim must cite and quote a primary record. A free Python gate drops what breaks the rules before any model time is spent, then a skeptic agent tries to refute the rest.
  • Reports: claim-ledger. Every point in a long report gets a stable ID, a testable statement, what would make it wrong, quoted evidence and a verdict. The template is enforced in code: one incomplete record rejects the whole batch, so no check is ever half-done.
  • Cost: claude-code-token-guard. Hooks deny the wasteful tool call at the moment it is made, and the denial message tells the agent what to do instead.

Each tool also has its own case study: the evidence pipeline, the claim ledger and the token guard.

How it was verified

  • Research. The public copy runs end to end offline on an invented 420-person family. In that run the free gate kept 12 of 16 claims and dropped 4 before any skeptic review.
  • Reports. Replaying the first ledger's 546 records through the tool reproduces its hand-made audit. The audit also shows where the value sits: batches 1 to 9 found problems in 27% of first checks, while batches 10 to 29 found 7% and took 73% of the work, so the tool reports when further checking stops paying.
  • Cost. Each hook targets a leak measured in my session logs, and each was confirmed by the numbers in the following week's scan.

Scope

  • The same model writes and checks, so the claim ledger labels any verdict that rests on the project's own notes for a person to verify.
  • The public research demo runs on an invented 420-person family.
