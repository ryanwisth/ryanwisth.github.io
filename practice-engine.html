Case study: product rules from a user problem

A practice app built around the mistake

A local practice app for any multiple-choice subject. It groups questions by the mistake they test, drills each mistake pattern until it is mastered under time, and grades timed sets on pacing as well as score.

3 in a rowcorrect and on time, on 3 different questions, to master a pattern
3, 7, 21days until a mastered pattern comes back for a check
2 filesone Python file and one HTML file run the app, with nothing to install

The problem

Practice by topic treats every miss in "percents" the same. But most misses come from one specific error: adding two percent changes instead of multiplying them, or averaging times instead of adding rates.

Practicing the whole chapter again does not target that error.

What I directed

I set the goals, the learning rules and the acceptance checks. The agents wrote the code.

  • The unit of practice is the mistake, not the topic. Each question belongs to one mistake pattern, and the app drills that pattern directly.
  • Speed is part of mastery. Knowing how to do something slowly is not the same as doing it under a clock, so a slow right answer does not extend the streak.
  • Mastery must span different questions. A streak on one repeated question proves memory.
  • A missed question is retired. Once its explanation has been shown, a later correct answer may be recall, so the question is never served again.
  • Pacing is a separate grade. A timed set can score well and still be paced badly. The report separates time that bought a right answer from time sunk into a wrong one.

How the results were verified

  • Tested by building the sample bank, running the app on localhost and exercising the drill, answer, timed-set, progress, pacing and audit functions.
  • The 21 sample questions each carry a machine check, and only checked questions are served.
  • A built-in audit flags bad answer keys, duplicate choices, near-clone questions and patterns with too few questions.
  • I verified the rules by using the tool for my own study.

The outcome

A working local app that anyone can load with their own questions from a spreadsheet file. The importer rejects the whole file if any row fails validation.

The public version is a generic, reduced build of a larger personal practice tool. A companion server in local-llm-mcp-servers lets a local AI model read how practice is going, read-only.

Honest limits

  • There are no automated tests in the repository yet.
  • Single user with no sign-in, meant to run on your own computer only.
  • Questions are text only, with no images or formulas.
  • The interface has not been checked across browsers.
