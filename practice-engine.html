Learning product · mistake-first design

A practice app built around the mistake

A local practice app that groups questions by the mistake they test, drills each mistake pattern until it is mastered under time, and grades timed sets on pacing as well as score.

Problem
Topic practice treats every miss in "percents" the same, but most misses come from one specific error: adding two percent changes instead of multiplying them, or averaging times instead of adding rates.
Result
A working app that drills each mistake pattern to mastery: 3 correct, on-time answers in a row on 3 different questions, then rechecks after 3, 7 and 21 days so mastery has to last. Timed sets are graded on pacing as well as score. It runs from 2 files with nothing to install and loads anyone’s own questions from a spreadsheet file.

The problem

Re-practicing the whole chapter never targets that one error. This app makes the error itself the unit of practice: every question is tagged with the mistake it tests, a pattern counts as mastered only after 3 correct, on-time answers on 3 different questions, and rechecks at 3, 7 and 21 days prove the fix held. One miss on a recheck reopens the pattern.

Decisions I made

  • The unit of practice is the mistake, not the topic. Each question belongs to one mistake pattern, so practice goes straight at the error behind the miss.
  • Speed is part of mastery. A slow right answer does not extend the streak, so mastered means right and on time.
  • Mastery must span different questions. The streak has to come from 3 distinct questions, because a streak on one repeated question proves only memory.
  • A missed question is retired. After its explanation is shown, a later right answer could be recall, so it is never served again.
  • Pacing is a separate grade. The report splits time that bought a right answer from time sunk into a wrong one.

How it was verified

  • Built the sample bank, ran the app on localhost and exercised drill, answer, timed set, progress, pacing and audit.
  • All 21 sample questions carry a machine check, and only checked questions are served.
  • A built-in audit flags bad answer keys, duplicate choices, near-clone questions and patterns with too few questions; the importer rejects the whole file if any row fails validation, so bad data never reaches a drill.
  • I verified the rules by using the tool for my own study.

Scope

  • Single user, runs on your own computer with no sign-in.
  • The public repository is a generic build of a larger personal practice tool.
