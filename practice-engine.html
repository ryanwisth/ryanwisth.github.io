Product rules from a user problem

A practice app built around the mistake

A local practice app that groups questions by the mistake they test, drills each mistake pattern until it is mastered under time, and grades timed sets on pacing as well as score.

Problem
Practice by topic treats every miss in "percents" the same. But most misses come from one specific error: adding two percent changes instead of multiplying them, or averaging times instead of adding rates.
Result
A working local app that anyone can load with their own questions from a spreadsheet file. The public version is a generic, reduced build of a larger personal practice tool.

The problem

Practicing the whole chapter again does not target that error.

Decisions I made

  • The unit of practice is the mistake, not the topic. Each question belongs to one mistake pattern, and the app drills that pattern directly.
  • Speed is part of mastery. A slow right answer does not extend the streak.
  • Mastery must span different questions. A streak on one repeated question proves memory.
  • A missed question is retired. Once its explanation has been shown, a later correct answer may be recall, so the question is never served again.
  • Pacing is a separate grade. The report separates time that bought a right answer from time sunk into a wrong one.

How it was verified

  • Tested by building the sample bank, running the app on localhost and exercising the drill, answer, timed-set, progress, pacing and audit functions.
  • The 21 sample questions each carry a machine check, and only checked questions are served.
  • A built-in audit flags bad answer keys, duplicate choices, near-clone questions and patterns with too few questions; the importer rejects the whole file if any row fails validation.
  • I verified the rules by using the tool for my own study.

Honest limits

  • There are no automated tests in the repository yet.
  • Single user with no sign-in, meant to run on your own computer only.
  • Questions are text only, with no images or formulas.
  • The interface has not been checked across browsers.
