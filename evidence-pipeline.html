Research that has to cite its records

A family tree grown only from records

A research pipeline where AI agents propose additions to a family tree, free Python checks what code can check, a second model tries to refute each claim, and accepted facts go into an append-only ledger.

Problem
Online family trees copy each other, so two trees agreeing is not evidence; it is often the same mistake copied twice.
Result
The pipeline ran three research rounds on a private tree in September 2026. In round 1 the skeptics rejected 31 claims from a fast first pass and 3 of 147 from a careful one.

The problem

A "source" on a big genealogy site is often just another user's tree.

In this pipeline every new person, parent link or date must cite a primary record (a register entry, a census line, a headstone), quote it, tie it to the tree person by at least two identifiers, and survive an adversarial check.

Decisions I made

  • Agents propose; code checks what code can check. On the private tree, round 2's finders averaged 78 turns. By round 3, dossiers, the gate and short review sheets had moved work into Python, and the round ran at about 57k tokens per target.
  • A second model tries to refute. The skeptic's stance is "when you cannot confirm, reject".
  • A free gate between the two agent waves. It drops claims that cite no record, have fewer than two identifiers, repeat a ledger fact, duplicate an existing child, or add a living person.
  • Quote matching is a window, not a phrase. The gate folds case, accents and punctuation, ignores field labels, and looks for 80% of the distinctive words inside one window. A miss flags the claim for the skeptic rather than dropping it.
  • Nothing is deleted. Disproved parent links are recorded and cut in later counts, and the base file is never edited.
  • Offline by default. Fetching is opt-in, with a fixed delay and a request cap.

How it was verified

  • The public copy runs end to end offline on an invented 420-person family with one command; every person, place and record in its sample and demo data is invented.
  • In that run the duplicate scan found the 3 injected duplicates, the merge took 423 individuals to 420, and the verifier checked the 3 merged individuals: 0 lost a fact.
  • The gate kept 12 of the journal's 16 claims and dropped 4.
  • The new GEDCOM is regenerated from the base file plus the ledger and checked: every base line survives and every pointer resolves.

Honest limits

  • The round figures come from the project's notes on the private tree; the demo does not reproduce them.
  • The agent scripts were not re-run after the scrub; they pass a syntax check only.
  • There is no record-pulling code in the repository; the saved page text has to be supplied.
